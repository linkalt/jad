## 1. Understanding note

Phase 8 is the persistence floor. `transcript` owns the golden `messages.jsonl` journal (`Journal`: append/repair/idempotent commit; durability process/turn/strict) and staged response turns (`TurnStore`/`ResponseTurn`: items.jsonl + index + manifest + final.jsonl, with crash recovery that recommits idempotently by line hash). Reads are layered: `InputHistory` memo (64 KiB tail-hash checkpoint), compaction-cache overlay (`readCompactionCache` + `compactionMemo`), cursor index (`cursor_cache.go`, checkpoint-hash window), plus sidecars that never enter the golden file (state-context, run-error cache, cursor/compaction caches). `imagestore` keeps large tool-result images out of the transcript as `<sha256>.<ext>` files with strict-name opens (Lstat + SameFile + content sniff). `imageresize` rewrites copies of history for the provider only (memoised by URL hash, bounded entries). `imagedata` decodes/validates caller-supplied base64. `contentlibrary` re-reads configured prompt/template/skill trees per request (documented refresh semantics). Prior fixes for this area are present in the tree (F-07 line index, F-02 size-first hash skip, P-012..P-014 fsync/syscall reductions) and were re-verified rather than re-reported.

## 3. Findings

### P8-R3-01  Commit observer runs while the per-turn mutex is held
- severity: low
- lens: A correctness
- location: backend-go/internal/transcript/turn.go:339-422 (CommitWithObserver; observer invoked after the journal append while t.mu is still held)
- evidence: [read] `t.mu.Lock()` at function start covers staging validation, manifest persists, `appendFileIfAbsent`, and the observer call before `os.RemoveAll`/unregister; panic is contained by `callCommitObserver`, but a blocking or turn-re-entering callback stalls staging cleanup under the lock. Live caller passes an app callback (backend-go/internal/session/runner_response.go:122, cross-phase lead). Fallback used: zvec-grep for callers plus read.sh exact ranges after trace_path rejected the short function name.
- suggested fix: document the observer as non-blocking and non-re-entering, or move the call after unregister/RemoveAll (recovery stays idempotent via the line hash); smallest change is the doc/guard comment in turn.go.
- effort: S
- prior art: new

### P8-R3-02  Cursor-index reads do not serialize with transcript rewrites
- severity: low
- lens: A correctness
- location: backend-go/internal/transcript/cursor_cache.go:59-113 (ReadCursorIndex takes only cursorMu); writers: backend-go/internal/transcript/maintenance.go:45-190 (CompactHistory, holds s.mu), backend-go/internal/transcript/front_compact.go:50-153, backend-go/internal/transcript/maintenance.go:656-681 (Reset)
- evidence: [read] a concurrent CompactHistory/FrontCompact/Reset can interleave a scan, yielding a transient stale index or the `transcript shrank while rebuilding cursor index` error; self-healing on the next read via `invalidateCursorCache` in `removeDerivedFiles`. Lock order s.mu->cursorMu already exists (removeDerivedFiles), so taking s.mu on the read path is consistent.
- suggested fix: hold s.mu (or check journal generation) across the match/scan/persist sequence in ReadCursorIndex; file: cursor_cache.go.
- effort: S
- prior art: new

### P8-R3-03  Library catalog reads every file fully on each request, with no size cap
- severity: medium
- lens: B security
- location: backend-go/internal/contentlibrary/library.go:161-230 (filesForKind/listKind read every match), backend-go/internal/contentlibrary/library.go:232-300 (recursive walk), backend-go/internal/contentlibrary/library.go:302-351 (readAsset: Lstat then os.ReadFile, unbounded)
- evidence: [read] `List` calls `readAsset` per file and `os.ReadFile` has no limit, on every request (per-request reload is the documented design); symlink entries are skipped (IsRegular/Lstat checks plus TestLibrarySkipsSymlinkEntriesAndDeduplicatesDirectories, run ok), but a configured root that is itself a symlink is followed via os.Stat, and two roots resolving to one tree duplicate entries (dedupe map is keyed by path string). Reachable by any API token holder once an operator-configured dir contains a large file; dirs are operator-trusted, hence medium, not higher.
- suggested fix: cap bytes read per asset (skip + log over cap), dedupe roots by file identity (os.SameFile); file: library.go.
- effort: M
- prior art: new (possible overlap with D-8/P-009, not verified against the current tree)

### P8-R3-04  imagedata.Decode copies the whole input before enforcing the size limit
- severity: low
- lens: B security
- location: backend-go/internal/imagedata/imagedata.go:28-60
- evidence: [read] `strings.Map` (full copy stripping whitespace) runs before the `len/4*3 > maxBytes+3` early reject, so an oversized input is duplicated before refusal; the bound itself is sound (upper bound for both Std and Raw alphabets) and decoded-size checks follow.
- suggested fix: length-gate the raw and post-strip estimate before the Map copy; file: imagedata.go.
- effort: S
- prior art: new

### P8-R3-05  Parent-directory fsync missing after transcript renames
- severity: low
- lens: D maintainability
- location: backend-go/internal/transcript/jsonl.go:84-132 (ReplaceRecords), backend-go/internal/transcript/front_compact.go:186-284 (ReplaceWithPrefix), backend-go/internal/transcript/maintenance.go:770-794 (writeCompactionJSONAtomic), backend-go/internal/transcript/turn.go:698-723 (writeJSONAtomic); contrast backend-go/internal/transcript/cursor_cache.go:227-287 (persistCursorCache syncs the directory)

- suggested fix: sync the parent directory after each publish rename, mirroring persistCursorCache; files listed above.
- effort: S
