## 1. Understanding note

Five provider paths.
1. `openaiapi.Client` wraps the OpenAI Go SDK for the Responses stream. The request is injected as raw JSON, one `WithJSONSet` per top-level key (client.go:221-245). Retry is the module's own loop with the SDK's retries off (client.go:124-160); the idle guard is a child context cancelled by a `time.AfterFunc` that is stopped while the handler runs or a retry waits (idle_guard.go). `responses` holds only the event and notifier types.
2. `app/resolver.go:488-522` builds the `http.Client`: nil by default, otherwise network transport (`provider_network`, `tcp4`/`tcp6`), then the OAuth transport, then the HTTP-debug transport on top. Commit 0bf03a1 is honoured by `openaiapi` through `Config.HTTPClient`, and tests `TestOAuthTransportUsesTheNetworkTransportAsBase`, `TestDebugWrapperDialsThroughTheNetworkTransport`, `TestUnsetProviderNetworkLeavesTheDefaultClientUntouched` pass (exit 0). The anthropic adapter does NOT honour it (`NewHandler(config, nil)` gives `&http.Client{}`, handler.go:26-29, `cmd/anthropic-adapter/main.go:41`), nor do the token refresh clients (`openaiauth.Client.httpClient`, `claudeauth.Client.httpClient`). Both are listed as "not covered" in DECISIONS.md (provider_network section), so these are recorded as sound-by-decision, not defects.
3. `openaioauth` is the backend's read-only reader of the credential file; it re-reads, re-parses and re-checks expiry on every HTTP request (credentials.go:67-119) and sets the headers in `Transport.RoundTrip`. Expiry in a run is a permanent `CredentialError` (no retry, `Permanent()`), so refresh depends on an external `openai-auth refresh` timer (DECISIONS).
4. `openaiauth` and `claudeauth` are the only writers: lock via `sessionlock`, read, `change`, atomic temp+fsync+rename+dir sync (store.go). Login = loopback callback + PKCE S256, state compared with `subtle.ConstantTimeCompare`.
5. `anthropicadapter` is a separate service: Responses in, Anthropic Messages out, stateless; own stream translator and SSE reader; reads `credential_file` on every request; logging allow-lists response headers and never logs request header values (log.go:398-428).

Prior art checked: A-4 rest (audit_performance_plan.md row A-4 and P-018: no action, idle guard covers the header wait), A-17 / D-7 (audit_audit.md item 11: recommended startup warning and an opt-in caller token; warning exists since f0ecac6 at cmd/anthropic-adapter/main.go:68-77, opt-in token not built), B-S1 (CORRECT: transport timeouts only). Nothing in DECISIONS conflicts with the findings below.

## 3. Findings

### P5-R1-01  OAuth transport re-adds the access token on every redirect hop
- severity: low
- lens: B security
- location: internal/openaioauth/transport.go:197-222 (sits below `http.Client`, so it runs again for each redirected request); wiring app/resolver.go:504-507
- evidence: [measured] probe `go test -overlay /tmp/r1/overlay.json ./internal/openaioauth/ -run TestProbeRedirectKeepsToken -count=1 -v` exit 0: a server answering 307 to a second host (`localhost` vs `127.0.0.1`) received `Authorization: Bearer <access token>`, `Chatgpt-Account-Id` and the caller's `X-Api-Key`. Go's client strips `Authorization` on a cross-domain redirect, but the transport then sets it again after the strip. Reachable only if the configured `base_url` (default chatgpt.com/backend-api/codex, or a user proxy) answers with a redirect to another host; `base_url` is trusted configuration, so impact is narrow.
- suggested fix: in `RoundTrip`, only attach the credential when `request.URL.Host` equals the host of the configured base URL (pass the allowed host into `Transport`), otherwise return an error; or set `CheckRedirect` to `http.ErrUseLastResponse` on the provider client built at app/resolver.go:505. Files: openaioauth/transport.go, app/resolver.go.
- effort: S
- prior art: new

### P5-R1-03  Any `*url.Error` counts as a retryable transport error, including TLS and scheme failures
- severity: low
- lens: A correctness
- location: internal/openaiapi/retry.go:55-92 (final `errors.As(err, &netError)`; `*url.Error` implements `net.Error`, only `Op == "parse"` is excluded at :86-89)
- evidence: [measured] probe `go test -overlay /tmp/r1/ov2.json ./internal/openaiapi/ -run TestProbePermanentTLS -count=1 -v` exit 0: `&url.Error{Err: x509.UnknownAuthorityError{}}` and an "unsupported protocol scheme" `*url.Error` both give `isRetryableError == true`. The synthetic errors stand in for what `http.Client.Do` returns; I did not run a real TLS server. Effect: a bad certificate or unusable base_url waits through all `MaxRetries` backoffs (each bounded by `MaxDelay`) before failing, and shows the user retry notices for an error that cannot recover. The comment at :76-79 already handles `Permanent()` for the OAuth case; TLS verification failures are the same class.
- suggested fix: before the `net.Error` test, return false for `x509.UnknownAuthorityError`, `x509.CertificateInvalidError`, `x509.HostnameError`, `tls.CertificateVerificationError` and for `*url.Error` whose inner error text is an unsupported scheme. File: openaiapi/retry.go.
- effort: S
- prior art: new (A-4 rest concerns timeouts, not classification)

### P5-R1-04  Adapter with `credential_file` set spends the subscription credential for any HTTP client that reaches the port, loopback included
- severity: medium
- lens: B security
- location: internal/anthropicadapter/credential.go:278-294 (`upstreamToken`: with `credentialPath` set no caller check at all); handler.go:36-78 (no `Host` or `Origin` check, no content-type check); cmd/anthropic-adapter/main.go:45-48 (`http.Server` without body or write timeouts)
- evidence: [measured] probe `go test -overlay /tmp/r1/ov.json ./internal/anthropicadapter/ -run TestProbeBrowserStyleRequest -count=1 -v` exit 0: a `POST /v1/responses` with `Content-Type: text/plain`, `Origin: https://evil.example`, `Host: rebind.evil.example:8788` and no Authorization header got status 200 and the fake upstream received `Authorization: Bearer <credential file token>`. A web page open in the user's browser can send exactly this as a CORS "simple" request (no preflight) to `http://127.0.0.1:8788`, spending the account (the response is unreadable without CORS, but the spend happens; with DNS rebinding the Host check is the missing piece and the response is readable). It needs `credential_file` set (default is empty, so default pass-through requires the caller to bring a key) and the listener on the default port. Also the 401 message returns the credential file path to the caller (credential.go:291, `credentialError.Error()`).
- This extends A-17 / D-7: the earlier recommendation (warning plus opt-in caller token) only covered non-loopback binds; the warning is done (main.go:68-77) and the token is not. New evidence is that loopback is also exposed to browsers.
- suggested fix: when `credential_file` is set, require a caller token (config key, constant-time compare as in `httpapi.authorized`) or at minimum reject requests whose `Origin` header is present and whose `Host` is not the listen address; require `Content-Type: application/json`. Files: anthropicadapter/config.go, handler.go.
- effort: M
- prior art: re-confirmed A-17 / D-7 (open, Low-Medium in audit_audit.md item 11), loopback/browser angle new; severity raised to medium on the probe

### P5-R1-05  A stray request to the login callback can abort the sign-in; claudeauth also registers the expected state late
- severity: low
- lens: A correctness
- location: openaiauth/login.go:173-178 and claudeauth/login.go:231-236 (`?error=...` ends the flow before the state is checked); claudeauth/login.go:78-92 (`expectState` runs after `OpenBrowser`), compare openaiauth/login.go:63-67 (before printing the URL)
- evidence: [read] Any local process or browser page can `GET http://localhost:<port>/auth/callback?error=x`; `finished` is set and `result` gets an error, so `Login` returns "refused by the issuer" and the user must start again. No secret is exposed. In claudeauth, a redirect that arrives before line 92 meets `c.state == ""`, gets 400 "not valid" and is not retried by the browser, which loses the sign-in; the window is the time between starting the browser and one line of code, so practically unreachable. Both are narrow.
- suggested fix: ignore `error=` unless `state` matches (RFC 6749 sends state with the error response); move `callback.expectState(request.State)` in claudeauth to right after `NewAuthRequest`. Files: openaiauth/login.go, claudeauth/login.go.
- effort: S
- prior art: new

## 4. Performance hypotheses for measurement

- H1: `rawRequestOptions` applies one `WithJSONSet` per top-level key; the SDK's sjson step copies the whole growing body each time (SDK option/requestoption.go:207-230 [read]), and the options run again on each retry attempt. Cost is O(keys x body size) per request on top of the `Unmarshal` into `map[string]RawMessage`. client.go:221-245, :126, :139.
  workload: a Responses request with a 5-50 MB `input` (image data URLs, long history), 12 top-level keys, 0 and 3 retries.
  benchmark: new `BenchmarkStreamLargeRequest` in openaiapi against an `httptest` server (copy the fixture of `BenchmarkStream`, client_benchmark_test.go:14-42, with a large `input`).
  expected: extra copies of about keys x body size and the same again per retry; compare with the existing `BenchmarkBuildRequestWithLargeHistory` (session) to see whether the provider layer matters.
- H2: per-event JSON validation in `Stream`: `json.Valid(raw)` on every event the SDK already parsed (client.go:95).
  workload: 10 000 delta events.
  benchmark: existing `BenchmarkStream` (10000-events), compare with the check removed in a scratch copy.
  expected: a small constant per event; likely below noise.
- H3: `openaioauth.Source.Load` does `os.Stat`, `os.ReadFile`, JSON decode and two JWT base64+JSON decodes on every HTTP request (credentials.go:67-119). One round of a run is one request, so it is paid per round.
  workload: 1 000 rounds in a long run, token file 5 KB.
  benchmark: new `BenchmarkSourceLoad` in openaioauth.
  expected: tens of microseconds per request against network latency of hundreds of ms; likely no action.
- H4: adapter stream translation allocates per upstream delta: `readSSE` builds a string per line and a joined string per event (stream_sse.go:126-137), `Unmarshal` of the event and again of the delta (stream.go:94, :237), `sseSink.event` copies the field map, marshals a `map[string]any` and concatenates the line (stream_sse.go:195-211).
  workload: 10 000 `content_block_delta` events of 5 tokens, one text block; and a 1 MB tool-argument stream.
  benchmark: new `BenchmarkTranslateStream` in anthropicadapter feeding a canned SSE body to `streamTranslator.run` with an `httptest.ResponseRecorder` sink (listed as a gap in audit_plan.md section 2).
  expected: about 8-12 allocations per event; scales linearly with events.
- H5: adapter request path copies large payloads several times: `Decode` into a map, `Unmarshal` into `responsesRequest`, per-item and per-part `Unmarshal` (input.go:233-241, parts.go:72), base64 `Data` strings copied into `anthropicBlock`, `json.Marshal` in `encodeRequestBody` (sdk.go:339-353, a second Unmarshal+Marshal when `extra_body` is set).
  workload: 20 MB request (several data-URL images, up to the 64 MiB cap).
  benchmark: new `BenchmarkTranslateRequestImages` in anthropicadapter; peak heap via `-benchmem`.
  expected: peak heap several times the request size.
- H6: each `providerHTTPClient` call with `tcp4`/`tcp6` clones a new `http.Transport` (app/provider_network.go:20-28, resolver.go:501); runners are cached per runner key, so sessions with different keys do not share connections and each pays its TLS handshake. Phase 1 code, recorded as a lead.
  workload: 20 sessions on `tcp4`, one round each.
  benchmark: `BenchmarkStreamConnectionReuse` (openaiapi/conn_reuse_benchmark_test.go) with one transport per client versus shared.
  expected: one handshake per session instead of per process.

## 6. Checked and sound

- provider_network honoured by the OpenAI path: unset leaves `http.DefaultClient` (resolver.go:497-503), OAuth and debug wrappers share one base transport (:505-518), dial error is prefixed with the setting (provider_network.go:23-26); three app tests exit 0.
- Token file refresh race: `Update` takes `sessionlock` before `Read` and holds it across the network call; `errSkip` writes nothing; the backend and adapter read without a lock but writes are temp+fsync+rename (openaiauth/store.go:220-257).
- File modes: temp file from `os.CreateTemp` is 0600; lock file 0600 (sessionlock/lock.go:94); backup written by the same function.
- `login --force` does not carry old tokens over (login.go:95-100); a file that appears during login is caught again under the lock (:92-94).
- Callback binding: loopback only (127.0.0.1 and ::1), state compared constant-time, empty state refused, first valid redirect wins, later ones get 409, pages never echo input, `ReadHeaderTimeout` set, servers shut down with a 1 s grace.
- PKCE: S256, 48-byte verifier (64 chars, inside RFC 7636 43-128), 24-byte state, `crypto/rand`.
- Token responses are limited to 1 MiB and errors carry status, code and a 200-byte description, never the body or a token; `File`, `Tokens`, `Credential` have redacting `String`/`GoString`.
- Secret logging in the adapter: only response-header allow-list, clipped body and header NAMES of the request are logged (log.go:398-428); `upstreamHeaders("")` is passed for names so the token never enters the log path.
- openaiapi retry: only the opening request is retried, `Retry-After-Ms`, `Retry-After` (seconds or date) and `x-ratelimit-reset` are bounded by `MaxDelay`, jitter reduces only, waits are context-aware (`sleepContext`), the guard is stopped while waiting, and a wait announced to the notifier is always cleared (deferred, client.go:133-137). `x-should-retry` is honoured both ways.
- Idle guard: child context, `defer release()` stops the timer and cancels (no timer outlives `Stream`), parent cancellation is not reported as idle (idle_guard.go:66-70).
- `withResponseBody` reads a body the SDK already buffered, restores it, and the client only sees the status (`StatusError`, executor.go:210-227).
- Adapter limits: request body capped by `LimitReader(max_request_bytes+1)` (handler.go:55-64), error bodies capped at 1 MiB (stream_handler.go:49), SDK retries off so the adapter's `stream_retry` is the only policy, `stream_retry` replays only before any event was written (`sink.events == 0`, `started` false, stream.go:141-143), client disconnect cancels the upstream through the request context.
- Config validation in all three config loaders rejects unknown keys and trailing data, bounds numbers, validates header names and rejects line breaks in extra header values; `extra_body` cannot override owned fields.
- No dead exported or unexported function in the six packages: a name-count scan (non-test grep for each declared function, flag if used once) returned nothing.
- build, vet, gofmt clean for the nine packages (exit 0 each).
