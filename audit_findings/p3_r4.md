## 3. Findings
### P3-R4-01  Concurrent interaction extension can resurrect an answered question
- severity: medium
- lens: A correctness
- location: `backend-go/internal/interactions/broker.go:188-190`, `backend-go/internal/interactions/broker.go:146-155`, `backend-go/internal/httpapi/interaction_state.go:26-52`
- evidence: [read] `Extend` snapshots the extended pending entry under Broker.mu, unlocks, then invokes notify; `Reply` independently settles under the same mutex, unlocks, then invokes the clearing notification. Since callbacks run after unlock, an extension callback can be delayed until after the reply-clearing callback. Both handlers are concurrent HTTP requests (`interaction_handlers.go:38,75`). `setPendingInteraction` accepts the delayed non-nil value whenever the run is still running, so it emits stale pending state after the answer cleared it. Broker tests exercise Extend then Reply sequentially, not reversed callback delivery.
- suggested fix: Preserve transition order when publishing broker state changes, or attach a monotonic state/version and discard callbacks older than current interaction state; add a deterministic concurrent Extend/Reply regression test.
- effort: S
- prior art: new

### P3-R4-02  HTTP-debug transport errors can leak credentials from query URLs
- severity: medium
- lens: B security
- location: `backend-go/internal/httpdebug/transport.go:99-104`, `backend-go/internal/httpdebug/transport.go:207-232`
- evidence: [read] On a RoundTrip error, the record stores a redacted URL at line 102 but stores raw err.Error() at line 103. The standard net/http url.Error returned for a failed provider request includes the request URL; with a configured base URL such as `https://provider.invalid/v1?api_key=secret`, a connection or DNS failure can therefore put `api_key=secret` in the debug file despite redactURL masking the URL field. This path is reachable when a session owner configures an upstream URL with a query credential and enables http_debug; existing redaction tests cover URL formatting, not error strings.
- suggested fix: Do not persist the raw URL-bearing error; record a sanitized cause that strips the request URL or remove the error field and retain status/transport category. Add a failed-RoundTrip redaction test.
- effort: S
- prior art: re-confirmed B-S2 / A-11 redaction fix in f5891c6; error-string path is additional evidence.

### P3-R4-03  Retained finished runs have no count or byte cap
- severity: low
- lens: C performance
- location: `backend-go/internal/httpapi/registry.go:297-308`, `backend-go/internal/httpapi/registry.go:786-827`
- evidence: [read] maxRuns tracks active runs only. Every completed run remains in the per-key runs slice until its retention timer calls retire; retained activeRun values keep terminal state including final UI messages. With a high run completion rate and long configured retention, retained run count and message bytes scale with rate times retention. No measurement was run. Re-confirmed prior B-C1.
- suggested fix: Consider a configured cap on retained runs or retained bytes with an explicit eviction policy, while preserving the documented attach/replay window.
- effort: M
- prior art: re-confirmed B-C1, previously accepted low; current map and finish paths still show no retained-run cap.
