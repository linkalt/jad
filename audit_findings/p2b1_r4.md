## 1. Understanding

The phase implements the catalog-layout session configuration loader and persistence path: it reads root/session/profile/model/toolset catalogs, validates and composes settings, tracks all configuration inputs for cache invalidation, checks catalog integrity, and persists selected profile/model defaults. Main risks are path/name containment across local files, atomic updates and concurrent readers, stale/missing settings-stamp inputs, validation drift, and the model-effort overlay. Catalog category symlinks are documented as a prior rejected concern (B-C4) and will not be re-raised without new evidence.

### P2B1-R4-02  Layout JSON parser accepts malformed trailing bytes
- severity: low
- lens: A correctness
- location: backend-go/internal/sessionfs/layout_files.go:180-193 (especially :189-192)
- evidence: [read] `parseLayoutFile` decodes one JSON value, then calls `decoder.Token()` and rejects only when that call succeeds. It therefore treats every error as end-of-input, including a syntax error from trailing junk (for example a valid object followed by `garbage`), and accepts the first object. `readLayoutFile` and the catalog/layout read paths feed files through this helper. Search of the scoped tests found no test mentioning its trailing-data error. No direct reproduction was run.
- suggested fix: require the second decode/token read to return exactly `io.EOF`; report all other errors as malformed trailing data, with valid-whitespace, second-value, and invalid-junk tests.
- effort: S
- prior art: new

### P2B1-R4-01  Session prompt documents are read without a byte or file-type bound
- severity: low
- lens: A correctness
- location: backend-go/internal/sessionfs/session.go:1120-1133 (especially :1129)
- evidence: [read] `loadPrompt` accepts session/profile `prompt_documents` and `readPromptDocument` resolves then calls `os.ReadFile` without a size limit or regular-file check. A configured FIFO can block settings loading; a device or very large file can consume unbounded memory while the prompt is assembled. This is the same file-read resource boundary as P2A-03, but the session/profile prompt reader is a separate path untouched by 336cdf4 and the current `session.go` has no later fix. No direct reproduction or test was run for this loader.
- suggested fix: route configured prompt reads through a bounded reader that rejects non-regular files and enforces a documented aggregate prompt budget; cover oversized and special-file inputs with tests.
- effort: M
- prior art: P2A-03 (fixed for previously reported native paths by 336cdf4; the separate session/profile `prompt_documents` path is not among the prior finding locations)

### P2B1-R4-03  Strict catalog writes do not sync parent directories
- severity: low
- lens: A correctness
- location: backend-go/internal/sessionfs/layout_settings.go:174-203; backend-go/internal/sessionfs/catalog_files.go:188-208,476-507
- evidence: [read] The app passes `settings.Persistence.Durability` to `SetLayoutModelDefault` (`backend-go/internal/app/session_settings.go:52`), and `WriteCatalogFile` is called with `syncWrite=true` (`backend-go/internal/app/catalog_files.go:74-86`). The update helper syncs the temporary file before `os.Rename`; the create helper syncs before `os.Link`; neither syncs the containing directory after publishing the entry. A crash/power loss can therefore lose a strict model-default replacement or a synced catalog create/update. No crash reproduction was run.
- suggested fix: sync the parent directory after `os.Rename`/`os.Link` for durable updates/creates (with platform-appropriate handling), and test strict model-default and catalog-write paths.
- effort: M
- prior art: new

### P2B1-R4-04  Catalog file reads follow symlinks outside the configured catalog
- severity: medium
- lens: B security
- location: backend-go/internal/sessionfs/catalog_files.go:116-126,169-182; backend-go/internal/app/catalog_files.go:62-72
- evidence: [read] `catalogPath` validates the `<category>/<name>` identifiers and joins them beneath the configured catalog directory, but `ReadCatalogFile` then calls `os.ReadFile` on the final path without checking that it is a regular non-symlink file. The app returns the resulting bytes from the catalog-read API. For example, if an untrusted local process/model with write access to a category creates `models/acme/leak.json -> /etc/hostname`, an authorized catalog reader requesting `acme/leak` receives the target file. No direct reproduction was run; the untrusted writer must be able to create that catalog symlink.
- suggested fix: reject final-component symlinks and non-regular files when opening catalog entries (prefer an `Lstat`/no-follow open with a post-open regular-file check); add a regression test that reads a catalog symlink to an outside file.
- effort: M
- prior art: new; distinct from rejected B-C4 category-directory symlink behavior.

## 4. Performance hypotheses for measurement (no benchmarks run)

- H01: `parseSessionObject` decodes each config byte slice twice (first to `any`, then to `map[string]json.RawMessage`) at `backend-go/internal/sessionfs/session.go:1179-1195`.
  workload: repeated loads of a session with many profile/model files or frequent settings invalidations.
  benchmark: existing `BenchmarkLoadSessionConfig` (`backend-go/internal/sessionfs/settings_load_benchmark_test.go`), extended to vary the number of JSON files and their size.
  expected: JSON parse CPU and temporary allocations scale with config-file count and bytes, with the object shape decoded twice per read; unmeasured. This is distinct from the p2a native-normalizer repeated section-decoding hypothesis.
- H02: `loadAgentToolsets` invokes `loadSessionSettingsFrom` once for each distinct non-empty agent toolset key (`backend-go/internal/sessionfs/layout_load.go:119-164`), re-normalizing session/profile settings for each derived tool config.
  workload: one session with many agents using distinct toolset combinations and nontrivial settings/prompt inputs.
  benchmark: existing `BenchmarkLoadSessionConfig`, extended with increasing agent/toolset counts and distinct keys.
  expected: settings normalization and related config reads grow with distinct agent toolset groups; unmeasured.
- H03: `ListCatalogFiles` reads every catalog entry in full to compute its SHA-256 ETag and display name (`backend-go/internal/sessionfs/catalog_files.go:129-147`).
  workload: 1,000 catalog files averaging 100 KiB, with repeated list requests during catalog-editor use.
  benchmark: proposed `BenchmarkListCatalogFiles` using generated profile/model/toolset files and varying both file count and size.
  expected: time and temporary allocations grow with total catalog bytes per list request; unmeasured.

- H04: A tracked input with a far-future mtime prevents SettingsStamp.Current from reusing settings (settings_stamp.go:51-65).
  workload: repeated conditional session-list polling for 200 sessions when one settings input has an mtime set one day ahead, compared with a normal mtime.
  benchmark: existing BenchmarkListManySessions/conditional/200, extended to set and restore a tracked input mtime in the fixture.
  expected: sessions with future-dated inputs take the settings reload path on every poll until wall-clock time catches up; cost is unmeasured.

### P2B1-R4-05 Future-dated input mtime prevents a settings stamp from becoming current
- severity: low
- lens: C performance
- location: backend-go/internal/sessionfs/settings_stamp.go:51-53, 58-65
- evidence: [read] fileStamp.racy returns true whenever taken.Sub(modTime) is less than the 2-second window. A file whose mtime is later than taken by more than that window produces a negative duration, which still satisfies the less-than comparison; SettingsStamp.Current then returns false before checking the unchanged path metadata.
