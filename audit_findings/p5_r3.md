## 1. Understanding note

p5 is the provider edge: (a) `openaiapi.Client` (Responses SSE `Stream` + `openStream` retry + `idleGuard`) used by `app.Resolver.newProviderStreamer` with a per-run `http.Client` built by `providerHTTPClient` (provider_network base → OAuth wrapper → http_debug wrapper); (b) `openaioauth.Transport/Source` (per-request file read, JWT expiry/account, no writer in backend); (c) `anthropicadapter.Handler` (Responses→Messages translation, per-request `upstreamToken` from caller header or `credential_file`, Anthropic SDK transport + own SSE parser + pre-output stream_retry, `MaxRequestBytes` 64MiB downstream, unbounded upstream SSE); (d) `openaiauth`/`claudeauth` CLIs + libraries (loopback `listenForCallback` on 127.0.0.1+::1, PKCE S256, state check, `Store.Update` under `sessionlock` + atomic 0600 write + `.bak`, `Refresh` inside the lock, `status Inspect` never prints tokens); (e) `responses` (neutral `Streamer` + `RetryNotifier` in ctx). `provider_network` (0bf03a1, DECISIONS 995-1007) forces tcp/tcp4/tcp6 only for the jad→provider dial (and via base for OAuth model requests); the adapter upstream dial and the token-endpoint clients are explicitly "Not covered". ## 4. Performance hypotheses for measurement (§5.3, all [unmeasured])

- H-01: `openaioauth.Source.Load` per model request — `os.Stat+ReadFile+Unmarshal+2×JWT parse` on every `RoundTrip` (transport.go:23-37, credentials.go:67-110). workload: 1 vs 100 sequential `Source.Load` on tmp file + one `RoundTrip` via `httptest` server. benchmark: new `BenchmarkOAuthSourceLoad` (none exists; closest `oauth_benchmark_test.go` is token-shape only). expected: ~10–100 µs/request, invisible vs provider seconds; unbounded only if file grows (unknown keys kept).
- H-02: `anthropicadapter.loadCredential` per adapter request — same shape (credential.go:37-73) + `h.now()` + margin check. workload: handler with/without `credential_file` at 1/100 req. benchmark: new `BenchmarkCredentialLoad` or existing `adapter_benchmark_test.go` + handler test harness. expected: same as H-01; cache with mtime would remove it but adds stale-token risk.
- H-03: `openaiapi.Stream` per-event `json.Valid` + `guard.Reset/Stop` (client.go:92-110, idle_guard.go:52-62 `timer.Reset/Stop` per event). workload: 1k vs 10k SSE events via `httptest` SSE server. benchmark: existing `BenchmarkStream` (client_benchmark_test.go:14-42). expected: `Valid` is O(event bytes) per event; timer churn is atomic + runtime timer, small vs network.
- H-04: `anthropicadapter` SSE translate + sink marshal per event (`stream_sse.go:20-61` `ReadString+Join`, `stream.go:87-137` `Unmarshal` per event, `stream_sse.go:77-120` `event()` `Marshal` per Responses event). workload: 1k vs 10k tool-use deltas. benchmark: existing `adapter_benchmark_test.go` (translation) + new stream-translate bench. expected: scales with events×bytes; whole-event `Unmarshal` dominates.
- H-05: `providerHTTPClient` rebuilds transport per sub-agent run when `tcp4/tcp6`/OAuth/debug (resolver.go:497-522, app/subagent.go:62 per p1 N09). workload: 1 vs 64 child runs with `tcp6`. benchmark: new (count `newNetworkTransport` calls + `CloseIdleConnections` absence). expected: extra Transport (proxy/TLS clone) per run, idle conns retained to 90 s; only pays when non-default network/OAuth/debug.
- H-06: `rawRequestOptions` per `Stream` sorts keys + `WithJSONSet` per field (client.go:221-245). workload: request with 10 vs 100 fields. benchmark: existing `BenchmarkStream` with varying request size. expected: O(fields log fields), negligible vs stream.
- H-07: `Refresh` under flock + `retryDelay` backoff cap (`retry.go:184-196` `min(requested, MaxDelay)`, `random()*0.25` down-jitter only). workload: cold (login/refresh), not hot; no benchmark needed unless A-4 fix changes it. expected: no hot-path effect.
