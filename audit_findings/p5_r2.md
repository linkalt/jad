## 1. Understanding note

- **`anthropicadapter`** is a standalone HTTP server (`cmd/anthropic-adapter`) that speaks the OpenAI Responses API and calls the Anthropic Messages API. `Handler.ServeHTTP` (`handler.go:36`) routes `POST /v1/responses` to `create` (`handler.go:49`), which resolves the upstream credential (`credential.go:112`), bounds and decodes the body (`MaxRequestBytes`, default 64 MiB, `handler.go:54-63`), translates it (`request.go:26` → `input.go`, `parts.go`, `tools.go`, `thinking.go`, `cache.go`), then calls `respond` (`handler.go:80`, non-streaming) or `respondStream` (`stream_handler.go:16`, streaming with an optional `upstream.stream_retry`). Output goes through `sseSink` (`stream_sse.go:66`) and the `streamTranslator` state machine (`stream.go:87-478`); the upstream body is parsed by the adapter's own SSE reader (`stream_sse.go:20`) over the raw body from `anthropic-sdk-go`, which is transport only (`sdk.go:15-23`, `WithMaxRetries(0)`).
- **`openaiapi`** is the backend's provider client: `Client.Stream` (`client.go:74`) wraps the official SDK's `Responses.NewStreaming`, validates each raw event (`client.go:95`), guards stream silence (`idle_guard.go:36`) and retries only the request that opens a stream (`client.go:124-160`, rules in `retry.go`). Its `*http.Client` comes from `app.providerHTTPClient` (`app/resolver.go:497-522`), which composes `provider_network` → OAuth transport → HTTP-debug transport, so the setting and both wrappers reach the provider hop.
- **`openaioauth`** is the read-only credential transport for `auth_mode: openai_oauth`: `RoundTrip` (`transport.go:23`) loads the file on every request (`credentials.go:67`) and rewrites the owned headers on a clone of the request.
- **`openaiauth` / `claudeauth`** are the two sign-in/refresh/status CLIs. Both write the credential file atomically under a `sessionlock` flock (`store.go:174-216`, `store.go:220-257`), read it without a lock (safe because of the atomic rename), and hold the lock across the token exchange so a rotating refresh token is spent once (`refresh.go:42-65`).
- **`responses`** is the provider-neutral stream contract (`stream.go:11-22`) plus the retry notifier that travels in the request context (`retry_notice.go:28-39`).

Concurrency model: the adapter `Handler` is shared by all requests and holds only immutable config, the SDK client and a logger; per-request state (`sseSink`, `streamTranslator`, `inputBuilder`) is allocated per request. `openaiapi.Client` is shared per runner and holds no mutable state (the `sleep`/`random` hooks are test seams); the idle guard's timer and `fired` flag are per call. The token-file readers never take the write lock, and the writer never exposes a partial file.

## 3. Findings

### P5-R2-01  Credential errors hand the credential file path to the client (adapter 401 and backend 422)
- severity: medium
- lens: B security
- location: backend-go/internal/anthropicadapter/credential.go:30-32, backend-go/internal/anthropicadapter/credential.go:98, backend-go/internal/anthropicadapter/credential.go:124; backend-go/internal/openaioauth/credentials.go:37-39 with backend-go/internal/app/oauth_client.go:33 and backend-go/internal/httpapi/handler.go:963-980
- evidence:
  - **[measured]** adapter: probe `/tmp/r2/cred_probe_test.go` (`go test -overlay ... -run TestProbeCredentialErrorLeaksPath ./internal/anthropicadapter/`, exit 0). With `upstream.credential_file` pointing at an expired file, `POST /v1/responses` answers
    `401 {"error":{"message":"Claude OAuth credential /tmp/Test…/001/claude-oauth.json: access token expired at 2020-01-01T00:00:00Z; refresh it with claude-auth refresh", …}}`.
    `loadCredential` builds `credentialError{Path, Reason}` (`credential.go:26-28`), `Error()` formats the path (`:30-32`), and `upstreamToken` copies it into the API error message (`:124`). The adapter authenticates no caller (A-17), so any process that can reach the listener sees the server's home layout.
  - **[read]** backend: in `openai_oauth` mode `resolver.apiKey` calls `checkOAuthCredential` (`app/resolver.go:471` → `app/oauth_client.go:29-38`), which wraps `openaioauth.CredentialError.Error()` — also path + reason — in a `StatusError{Code:422}`; `normalizeResolverError` passes it through (`httpapi/handler.go:959-971`) and `writeJSONError` writes `{"error": <message>}` (`httpapi/handler.go:980`). `DECISIONS.md:380` records the opposite intent: "The client sees a generic failure … The file path and reason go to the server log." The repro would need the `app` fixture, hence `[read]` here.
- suggested fix: keep `Path` out of `Error()`; add a `Message()`/`Reason()` used for client-facing text and log the path through the existing logger (`anthropicadapter/log.go:15`, `app` logger). Add one test per reader asserting the response body/HTTP error contains no `/` and no `Path`. Files: `internal/anthropicadapter/credential.go`, `internal/openaioauth/credentials.go`, `internal/app/oauth_client.go`.
- effort: S
- prior art: new for the disclosure itself; `DECISIONS.md:380` is the decision it contradicts (a behaviour recorded there is not a finding, but this is the opposite of it, so it is raised as a defect, not a decision challenge)

### P5-R2-02  The adapter abandons the upstream stream at `message_stop`, so an HTTP/1.1 upstream pays a new connection per round
- severity: medium
- lens: C performance
- location: backend-go/internal/anthropicadapter/stream.go:114-115 (the reader stops as soon as the terminal event is written), backend-go/internal/anthropicadapter/stream_sse.go:24-30, backend-go/internal/anthropicadapter/stream_handler.go:71 (`_ = stream.Close()`), handler.go:26-29 (`&http.Client{}` = one pool per process)
- evidence: **[measured, relative]** two overlay probes in `/tmp/r2` against an `httptest` upstream counting `http.StateNew` (`go test -overlay`, both exit 0):
  * whole SSE body in one write: 2 streaming calls → **1** new upstream connection (reused);
  * realistic stream (every event flushed, 2 ms apart, 50 ms of life left after `message_stop`): 3 streaming calls → **3** new connections (never reused).
  Cause: `streamTranslator.run` returns at `message_stop` leaving the terminating bytes unread, so `stream.Close()` discards the connection instead of pooling it.
- workload: every provider round of every session that points `base_url` at the adapter; one extra TCP+TLS handshake per round. The default upstream (`https://api.anthropic.com`) negotiates HTTP/2, where an early body close resets the stream and not the connection — so today's cost is certain only for an HTTP/1.1 upstream (a local proxy or gateway). **The time cost was not measured**; the measurement step should time a round against an HTTP/1.1 fixture with and without a drain.
- suggested fix: before `stream.Close()`, drain what is left with a bound: `_, _ = io.Copy(io.Discard, io.LimitReader(upstream.Body, 64<<10))` in `stream_handler.go` next to `:71` (both the success and the failure return). No change to the SSE parsing or the emitted events.
- effort: S
- prior art: new (P-018 measured the *openai* client's reuse and lost nothing; `audit_performance_plan.md` Phase 3 Q8 asked the same question about the adapter and never answered it)

### P5-R2-03  `provider_network` does not reach the adapter's own upstream connection
- severity: low
- lens: D maintainability (a setting promises more than it does), B
- location: backend-go/internal/anthropicadapter/handler.go:26-29, backend-go/cmd/anthropic-adapter/main.go:41, backend-go/internal/anthropicadapter/config.go:216-268 (no network key); the setting: backend-go/internal/sessionfs/provider_network_settings.go:13, applied at backend-go/internal/app/resolver.go:497-522
- evidence: [read] `provider_network` is a session setting; `app.providerHTTPClient` applies it to the hop from the backend to `model.base_url` — i.e. to the connection **into** the adapter — and `openaioauth.Transport.RoundTrip` keeps that base (`transport.go:44-48`), so both wrappers honour it. The adapter's own dial to `upstream.base_url` uses `&http.Client{}` (default transport, no attempt to force a family) and its schema has no such key. A user who sets `provider_network: tcp4` to work around a broken IPv6 route therefore fixes only the local hop; the hop that reaches Anthropic still races both families. `DECISIONS.md:995-1003` does not say this.
- suggested fix: add `upstream.network` (`tcp`/`tcp4`/`tcp6`, default `tcp`) to the adapter config and build the transport as `app.newNetworkTransport` does (`app/provider_network.go:18-27`), or state the limitation in `cmd/anthropic-adapter/README.md` and `DECISIONS.md:995-1003`. Files: `internal/anthropicadapter/config.go`, `handler.go`, `sample/schemes/anthropic-adapter.schema.json`, `cmd/anthropic-adapter/README.md`.
- effort: S
- prior art: new (0bf03a1 `provider_network` had not been reviewed; the phase-1 half is sound, section 6)

### P5-R2-05  `errors.Unwrap(err).Error()` relies on every `os` error being a `*PathError`
- severity: low
- lens: A correctness (latent), D maintainability
- location: backend-go/internal/anthropicadapter/credential.go:52, :66; backend-go/internal/openaioauth/credentials.go:75, :84; backend-go/internal/openaiauth/store.go:161, :206
- evidence: [read] `errors.Unwrap(err).Error()` is called on `os.Stat`/`os.ReadFile` results. Today both return `*fs.PathError`, whose `Unwrap` is non-nil, so no nil dereference is reachable; the code silently depends on that and would panic if any future `fs` implementation returned an error without an inner error. The neighbouring code (`credentialError.Reason`, `store.go:159`) shows the safe shape.
- suggested fix: `fmt.Errorf("cannot be read: %w", errors.Unwrap(err))` (prints `<nil>` instead of panicking) or drop the `Unwrap`. Files as listed.
- effort: S
- prior art: new

### P5-R2-06  The adapter's SSE reader has no per-event size bound
- severity: low
- lens: B security (limits on untrusted sizes), C memory
- location: backend-go/internal/anthropicadapter/stream_sse.go:19-33 (`ReadString('\n')`, `strings.Join(data, "\n")` at :29), backend-go/internal/anthropicadapter/stream.go:78, :94
- evidence: [read] `bufio.Reader.ReadString` grows without limit and every `data:` line of one event is joined into one string, which is then unmarshalled. The only bound in the adapter is `max_request_bytes` (64 MiB) on the request side (`handler.go:54-63`); the smallest bound on the response side is `errorBodyLimit` 1 MiB, used only for an upstream error body (`stream_handler.go:80`). A compromised, substituted or misconfigured `upstream.base_url` (operator config, so local) can make the adapter allocate without limit, and `stream_retry` replays it.
- suggested fix: `upstream.max_event_bytes` (default e.g. 16 MiB) enforced in `readSSE`; on overflow fail the stream with `response.failed` and code `upstream_stream_too_large`. Files: `internal/anthropicadapter/stream_sse.go`, `defaults.go`, schema.
- effort: S
- prior art: new

## 4. Performance hypotheses for the measurement step

- H01 (P5-R2-02): the adapter opens a new upstream connection per streaming round when the upstream is HTTP/1.1. `stream.go:114-115`, `stream_handler.go:71`.
  workload: N streaming rounds against one HTTP/1.1 upstream, N = 2 and 20.
  benchmark: none exists for connection counts; use the probe shape in `/tmp/r2/reuse_probe2_test.go` (an `httptest` server with `ConnState` counting `StateNew`, events flushed 2 ms apart) and report new connections per call, plus wall time per round on an HTTP/1.1 fixture and on `httptest.NewTLSServer` (h2) for the contrast; existing timing counterpart `BenchmarkStreamThroughAdapter` (`anthropicadapter/adapter_benchmark_test.go:45`).
  expected: 1 new connection per round today (HTTP/1.1), 0 with a bounded drain; per-round time falls by the handshake cost; nothing on h2.
- H02: the adapter decodes and re-encodes the request more than once per call. `request.go:26-35` unmarshals the body into `map[string]json.RawMessage` and again into `responsesRequest`; `sdk.go:45` marshals the whole translated request, and with `extra_body` unmarshals and re-marshals it (`sdk.go:51-58`).
  workload: request bodies of 1, 10 and 50 conversation turns with 20 tools.
  benchmark: `BenchmarkTranslateRequest` (`adapter_benchmark_test.go:27`), extended in `/tmp` with the 10- and 50-turn fixtures to show whether the cost scales linearly with history (it should be linear; the question is the constant).
  expected: linear in history size, with two full parses and one full marshal per call; an avoidable constant of roughly one parse.
- H03: `openaiapi.Stream` validates and re-reads every event (`json.Valid` per event, `client.go:95`, `RawJSON` at :94), on top of the SDK's own decode.
  workload: 1k and 10k events.
  benchmark: `BenchmarkStream` (`openaiapi/client_benchmark_test.go`); prior art already has numbers (P-011: 11 KB and 18 allocs per event, 85 % inside the SDK) — re-measured only if a fix is proposed, otherwise "no repo-side fix" stands.
  expected: the repo's own share is small; the SDK dominates.
- H04 (closure, not a measurement): `openaioauth.Source.Load` stats, reads, unmarshals and parses two JWTs on every provider request (`credentials.go:67-119`); already measured at 10.9 µs / 31 allocs per request (`audit_performance_plan.md`, Phase 0). Not worth changing.

## 6. Checked and sound (with the evidence that settled it)

1. **`provider_network` is honoured end to end by the backend's provider client.** `app.providerHTTPClient` builds `newNetworkTransport` and passes it as the base of the OAuth transport and then of the HTTP-debug transport (`resolver.go:497-522`); `openaioauth.Transport.RoundTrip` delegates to `t.Base` (`transport.go:44-48`); the setting is part of the runner identity (`resolver.go:1089-1109`). Only the adapter's own dial is outside it (P5-R2-03).
2. **OAuth callback binding.** Both login servers listen on `127.0.0.1` and `::1` only (`claudeauth/login.go:186-211`, `openaiauth/login.go:128-152`), set `ReadHeaderTimeout: 10s` (`:207`), compare `state` with `subtle.ConstantTimeCompare` and reject an empty expected state (`:238`), and their pages never echo request values (`:248-253`). `redirect_host` is validated as a bare host (`config.go:124`) and `X-1` already covers the DNS-rebinding residue — not re-raised.
3. **Token-file writes and reads cannot interleave partially.** `writeAtomic` writes a `0600` temp file in the target directory, `Sync`s, closes, renames, then best-effort syncs the directory (`openaiauth/store.go:220-257`; same shape in `claudeauth/store.go`). Readers (`openaioauth.Load`, `anthropicadapter.loadCredential`) take no lock and therefore never block a writer and never see a partial file.
4. **Refresh races.** The whole exchange runs inside `Store.Update` under the `sessionlock` flock (`store.go:174-216`, `refresh.go:42-65`), so a rotating refresh token is spent once; `TestConcurrentRefreshesAreSerialised` (`openaiauth/store_test.go:235`) passes in the run below. The exchange is additionally bounded by `http.Client.Timeout` (`token.go:63-68`).
5. **A retry cannot replay after output.** `openaiapi` retries only when `stream.Err()` is set before any event is read (`client.go:138-159`, `retry_test.go:364`), and the adapter requires `!started && sink.events == 0` before it reports a retryable error (`stream.go:141-151`); a `message_start` alone does not open the sink (`stream.go:160-186`). `TestStreamDoesNotRetryAFailureAfterEventsArrived`, `TestStreamStopDuringAWaitReportsTheStopAndMakesNoFurtherRequest` pass.
6. **The idle guard measures provider silence only.** It is stopped around the event handler (`client.go:99-103`) and around a retry backoff (`client.go:153-158`), and a caller stop is never reported as idle (`idle_guard.go:66-70`); `idle_guard_test.go:80,111,139,177` cover all three and pass.
7. **Secrets stay out of logs and errors.** The adapter logs the status, an allow-listed header set and a clipped body, and the *names* of the headers it sent (`log.go:43-70`); `Set-Cookie` is not on the allow-list and `log_test.go:52-60` asserts it. `Tokens`, `File` and `Credential` print as `redacted` (`openaiauth/token.go:25-26`, `store.go:32-33`, `openaioauth/credentials.go:26-27`). Token-error text carries only status/code/description, bounded to 2 KB of body (`token.go:105-168`), and a JSON decoder error is never echoed because it can quote file content (`credentials.go:88-91`, `store.go:38-44`).
8. **A caller cannot smuggle headers upstream.** `upstreamHeaders` builds the outgoing header set from config plus the extracted token only (`handler.go:143-159`); the caller's own headers are not copied (`apiKeyFrom`, `handler.go:163-168`), and `extra_headers` may not name a reserved header (`config.go:296-306`).
9. **Config validation is complete for what it promises.** Unknown fields rejected (`config.go:202-214`), every numeric key range-checked (`:216-268`, `:270-327`), `extra_body` cannot override a field the adapter builds (`:329-337`), `effort_map`/`effort_budget` keys and values checked (`:347-368`), `models[].match` compiled once at load (`:369-380`).
10. **Bounded inputs.** Request body limited by `MaxRequestBytes` (64 MiB default) with `LimitReader` (`handler.go:54-63`); upstream error body limited to 1 MiB (`stream_handler.go:80`); token responses limited to `MaxTokenResponseBytes` (`token.go:117-123`).
11. **Timeouts.** Adapter upstream calls carry a whole-request context timeout (`handler.go:81`, `stream_handler.go:17`, default 600 s) plus the SDK's per-request timeout option (`sdk.go:64`), so the adapter half of A-4 is covered; the backend half is the idle guard (P-018, "no action") and `idle_timeout_ms = 0` remains the documented opt-out. No `ResponseHeaderTimeout` exists anywhere in the phase — covered by the guard, not re-filed.
12. **`provider_retry` follows `DECISIONS.md:183-196`** on which statuses retry, `x-should-retry`, `Retry-After`/`Retry-After-ms`/`x-ratelimit-reset` parsing and the cap (`retry.go:43-196`); `retry_test.go:74,103,141,180` pass.
13. **`responses`** is a 62-line contract with no state; `WithRetryNotifier(ctx, nil)` returns the parent context (`retry_notice.go:28-33`), and `RetryNotifierFrom` is safe on a context without the value.
14. **Exit codes and output of the CLIs.** `openai-auth`/`claude-auth` return 3 for "sign in again" and 64 for usage (`cmd/openai-auth/main.go:22-27`, `cmd/claude-auth/main.go`), and `status` never prints a token (`internal/*/status.go`); `cmd/*` tests pass.
15. **Toolchain.** `go vet` and `gofmt -l` are clean on all nine packages; all eight phase test packages pass (`ok`), matching the baseline.
