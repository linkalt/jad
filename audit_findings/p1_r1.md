## 1. Understanding note

`cmd/jad` loads config (`app.LoadConfig`: root setting, `HOST`/`PORT` env, `JAD_API_TOKEN`), builds the `Service` (resolver + httpapi handler + optional remote API server), listens on TCP, and when `server.remote_api.listen_unix` is set also on a private unix socket that serves only `/api/remote/v1`. Without `listen_unix`, `HandlersFor` routes `/api/remote/*` to the remote server on the main (plain http) listener. The remote server (`remoteapi`) authenticates sha256-hashed bearer tokens from a reloaded file, enforces per-token action and profile/agent globs, deduplicates starts by `(token, request_id)`, and delegates to `app.remoteBackend`, which starts an ordinary profile run (through the same `httpapi.ProfileRunStarter` as `profile_message`) or the profile's own `subagent` tool through `native.WithExternalRun`. Transcript reads are served by the real `transcript`/`transcripts` tools wrapped in `tokenProfiles` (glob view, no paths). The client side (`remote`) is entry files + a per-entry `http.Transport` (no proxy, no redirects, response cap, retries only for idempotent calls and starts with a request id) held in a `Hub` that owns follower goroutines.
`Resolver` owns every shared manager (process, subagent, async host, task/memory/fetch, MCP) under one `mu`, plus the transcript store cache; `Close` drains them in a fixed order. `asyncmgr` is the single handle/record store behind all async tools (in-memory rows + `<id>.json` records + coalesced `index.json`). `checkpoint` snapshots the workspace into a private bare git repo per session (ctx plumbed through git in 65fdb84).

### p1-r1-01  Wildcard-host check lets "0", "0.0", "0x0", "00", "0.0.0" through; with the cgo resolver they bind every interface
- severity: medium
- lens: B security
- location: backend-go/internal/app/config.go:141-160 (`listenHostPattern`, `listensOnEveryInterface`), :167-175 (`checkRemoteListenHost`)
- evidence: [measured] `/tmp/r1/h`: `net.Listen("tcp","0:0")`, `"0.0:0"`, `"0x0:0"`, `"00:0"`, `"0.0.0:0"` succeed and bind `[::]:port` under `GODEBUG=netdns=cgo` (getaddrinfo accepts inet_aton short forms); under the pure-Go resolver they fail closed ("no such host"). `netip.ParseAddr("0")` fails and the host matches `listenHostPattern` (digits and dots are valid labels), so `listensOnEveryInterface` returns false and `HOST=0` (or `server.host:"0"`) with `server.remote_api.enabled` and no `listen_unix` passes `checkRemoteListenHost`. The cgo resolver is the default on macOS and on Linux with some nsswitch setups; this repo builds with CGO (go env CGO_ENABLED=1). Result: the remote API and its clear-text bearer tokens listen on all interfaces, the exact case the check exists to refuse (DECISIONS "Remote JAD calling"). Reachable by an operator mistake/habit (`HOST=0`), then by any network peer. Existing test `config_test.go:129-142` has no all-digit/short form.
- suggested fix: treat a host made only of digits and dots (and hex `0x` forms) as an address, not a hostname: refuse unless it parses with `netip.ParseAddr`; or require that a non-IP host not start with a digit-only label. Add the five spellings to the wildcard table in config_test.go. Files: internal/app/config.go, config_test.go.
- effort: S
- prior art: new (remote range, be4af1d..a21104b, 8028576, a57403b)

### p1-r1-02  Checkpoint restore removes files through a symlink that restore itself just recreated (path escape out of the workspace)
- severity: medium (promote to high if a Service-level test confirms; primitives reproduced, composed path not executed)
- lens: B security

## 4. Performance hypotheses for measurement

- H01: `Resolver.mu` held while `asyncmgr.Open` reads/writes records, resolver.go:602-618.
  workload: 100 sessions × 2 profiles with a `.async` folder holding 100 unread + 200 terminal rows; `recover_*_at_start` on; 8 concurrent `Resolve`/list calls.
  benchmark: new `BenchmarkResolverAsyncHostOpen` (fixture above) plus lock-hold histogram via a wrapper counter on `r.mu`.
  expected: stall equals the sum of open times; after the fix other lookups stay at map-lookup cost.
- H02: per-child provider transport/connection when `provider_network`≠tcp (or OAuth/debug), subagent.go:62, resolver.go:481-515.
  workload: 50 sequential sub-agent runs against an `httptest` TLS server, `provider_network: tcp4`.
  benchmark: new `BenchmarkSubagentProviderClient` counting accepted connections and handshakes; compare with default settings.
  expected: ~1 handshake per child vs ~1 per process; idle connections linger up to 90 s.
- H03: remote `transcript`/`transcripts` rebuild settings + compile the tool schema + validate per request, remote_transcripts.go:97-122.
  workload: 10 GET/s for one token against a 1 MiB transcript.
  benchmark: new `BenchmarkRemoteTranscriptRequest` (httptest server over `remoteBackend` with a fake profile).

- H05: `profileMessenger.Profile` loads full session settings per profile name; `transcripts` profile listing calls it N times, transcript_profiles.go:35, tools/native/transcripts_list.go:198.
  workload: one session with 20 profiles, `transcripts path=session:<id>` 10×.

## 6. Checked and sound
